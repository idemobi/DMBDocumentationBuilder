# DMBDocumentationViewer Troubleshooting

## Project-specific section

When copying this file to another PageBuilder ecosystem project, update this section first.

- Project name: `DMBDocumentationViewer`
- Main troubleshooting areas: missing generated databases, route values, SQLite query filters, empty documentation records, sidebar provider fallback, MCP endpoint setup, embedded Razor views, source-code lookup, and project-context lookup.
- Resource folder: host-dependent; no local resource folder is required by default.
- Documentation target: `labs_idemobi_com`

## Documentation page returns no content

### Symptoms

- The documentation route loads, but the page body is empty or shows a missing object state.

### Checks

1. Verify the generated SQLite database exists for the requested package and version.
2. Verify `groupName`, `packageId`, `version`, `namespaceName`, `objectName`, and `objectType` match stored documentation records.
3. Confirm the requested object was generated by the documentation builder pipeline.
4. Confirm the controller fallback values do not point to a different package or version.

## Search returns no result

### Checks

1. Confirm the query string is not empty after trimming.
2. Confirm `packageId` and `version` filters match generated records.
3. Confirm keywords and technical keywords were generated for the target objects.
4. Confirm the search service is pointed at the expected SQLite database path.

## MCP tool returns weak or empty context

### Checks

1. Confirm the MCP endpoint is registered through `DocumentationViewerConfiguration`.
2. Confirm the same query works through the runtime query service.
3. Verify source-code and project-context records exist in the generated database.
4. Keep MCP responses concise; do not expand the formatter with unrelated records.

## Sidebar is missing or too sparse

### Checks

1. Confirm the host application assigned `DocumentationSidebarFactory.Provider`.
2. Confirm the provider implements root, group, and namespace sidebar methods consistently.
3. Confirm route values passed to the provider match the current documentation page.
4. Use a documented fallback when no provider is available.

## Embedded view is not found

### Checks

1. Confirm `Views/**/*.cshtml` are embedded by the project file.
2. Confirm the host application has registered the package configuration.
3. Confirm the controller action returns a view name that exists under `Views/Documentation/`.
4. Avoid renaming embedded views without updating the controller and documentation.

## Source code lookup returns no snippet

### Checks

1. Confirm the documented object has source-code records in the generated database.
2. Verify package id, version, namespace, object name, and object type filters.
3. Confirm source snippets were enabled when the database was generated.

## Documentation output quality is weak

### Checks

1. Confirm docs follow `DOCUMENTATION_RULES.md`.
2. Confirm examples and tutorials use `EXAMPLES_AND_TUTORIALS_RULES.md` only when those pages are being changed.
3. Confirm headings are deterministic for extraction.
4. Confirm audience needs (developers + AI) are addressed.
